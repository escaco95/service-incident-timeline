# 데이터 내보내기와 복원

로그인 후 **시스템 설정 → Danger Zone**에서 사용합니다. 내보내기·검증은 별도 작업 스레드에서 날짜별 파일을 순차 처리하며 전체 ZIP을 서버나 브라우저 메모리에 올리지 않습니다. 비밀번호와 암호화 키는 ZIP에 포함하지 않습니다. ZIP의 JSON에는 워크플로우 비밀 변수를 포함한 복호화된 데이터가 들어갑니다.

## 화면 흐름

- **내보내기:** 데이터 내보내기 → 데이터 내보내는 중… → 원래 버튼과 `YYYY_MM_DD.zip 다운로드` 버튼 표시. 날짜는 시스템 설정의 시간대를 따릅니다. 다운로드는 브라우저의 파일 다운로드 기능을 사용합니다.
- **복원:** 데이터 복원하기 → ZIP 선택 → 업로드 중… → 복원 데이터 검사 중… → 원래 버튼과 `파일명 데이터로 복원` 버튼 표시. 검증한 이벤트·변경 기록·실행 이력 건수를 보여줍니다.
- **적용:** 데이터로 복원 → 전체 교체 확인 팝업 → 별도의 현재 비밀번호 입력 팝업 → 비동기 복원 → 갱신된 화면. 검증 단계에서는 현재 기록과 설정을 변경하지 않습니다. 비밀번호가 틀리면 적용하지 않으며 로그인도 유지합니다.

같은 브라우저 세션에서 화면을 새로고침하거나 설정을 다시 열면 진행 중인 작업과 준비된 파일을 조회할 수 있습니다. 로그아웃, 초기화, 서버 종료·재시작에서는 임시 작업을 정리합니다. 서버가 비정상 종료되어 남은 작업 디렉터리도 다음 시작에서 정리합니다.

## 범위와 실행 기준

이벤트, 서비스 목록, 워크플로우 구성·비밀 변수, 변경 기록·실행 이력, 브랜딩·시간대·비밀번호 안내문과 로그 관리 정책을 전체 교체합니다. **현재 로그인 비밀번호는 유지**하며 그 키로 복원 데이터를 다시 암호화합니다. 새 설치에서 새 비밀번호를 설정한 뒤 기존 ZIP을 복원하는 것도 가능합니다.

로그인 세션, 초기화 요청의 중복 방지 정보, 진행 중인 로그 정리 작업, 파일별 조회 인덱스는 백업에서 가져오지 않습니다. 조회 인덱스는 검증한 기록으로 다시 만듭니다. 이벤트·설정의 편집 버전도 새로 발급하여 복원 전 편집본과 충돌하도록 합니다.

내보내기는 암호화된 불변 파일의 스냅샷을 확보한 뒤 진행하므로 처리 중 이후에 추가·수정한 기록이 ZIP에 섞이지 않습니다. 스냅샷 확보 동안 저장 큐를 잠시 사용하며 이후 압축 중에는 일반 작업을 계속할 수 있습니다.

복원 적용 시 새 일반 API 작업을 막고 먼저 접수한 요청을 마친 뒤 실행 중인 워크플로우와 정리 작업을 중지합니다. 복원한 미완료 실행은 `interrupted`로 기록하고 자동 재개하지 않습니다. 워크플로우 ON/OFF 설정은 복원하며 지난 시작·종료·cron 시각은 소급 실행하지 않습니다. 적용 후 다른 로그인 세션을 종료하고 요청한 세션은 유지합니다. `데이터 복원` 변경 기록을 남깁니다.

## 파일 검증과 실패 처리

지원하는 ZIP은 이 앱에서 내보낸 형식 버전 1입니다. ZIP 파일 구조·CRC, 파일 목록과 SHA-256, 설정 schema, 이벤트·서비스·워크플로우 구조, 날짜별 배치, 기록 ID·실행 요청 ID 중복과 건수를 검증합니다. 경로 이탈, 심볼릭 링크, 암호화 ZIP, 알 수 없는 추가 파일, 누락·손상·중복 파일, 과도한 압축 해제 크기는 거부합니다. SHA-256은 파일 간 일관성 검사이며 작성자의 서명은 아닙니다.

검증한 기록을 별도 디렉터리에 암호화하여 준비합니다. 적용할 새 날짜 파일을 확보한 뒤 `.restore-pending.json`에 승인된 복원을 기록하고 관리 파일과 브랜딩을 교체합니다. 이 기록 전 실패하면 현재 관리 파일을 보존합니다. 기록 후 실패하면 일반 API를 차단하며, 파일 권한·남은 공간 문제를 해결하고 서버를 재시작하면 승인된 복원을 완료합니다. 이때 `.restore-pending.json`을 임의로 삭제하지 않습니다. 이미 외부 API에 적용된 작업은 복원으로 되돌릴 수 없습니다.

## 용량과 임시 보관

기간 자체보다 기록 건수와 파일 용량에 따라 작업 시간과 필요한 공간이 달라집니다. 2016년부터 2025년까지 3,653개 일별 기록을 실제로 내보내고 복원하는 통합 테스트를 제공합니다.

| 항목 | 현재 한도 |
| --- | --- |
| ZIP 파일 | 8 GiB |
| 전체 압축 해제 데이터 | 32 GiB |
| 개별 JSON 및 암호화 날짜 파일·인덱스 | 각각 64 MiB |
| ZIP 항목 | 20,000개 |
| 동시에 처리하는 내보내기·검증·복원 | 전체 1개 |
| 준비된 작업 | 내보내기 1개, 복원 1개 |
| 준비 완료 후 사용 가능 시간 | 최대 24시간 |
| 내보내기·업로드·검증 작업 | 시작 후 최대 2시간 |
| 다운로드 | 동시에 2개, 개별 최대 2시간 |

새 내보내기 요청을 접수하면 기존 내보내기 ZIP과 임시 작업 파일을 먼저 삭제하고 새 ZIP을 생성합니다. 생성 실패 시에도 이전 ZIP은 남기지 않습니다. 같은 `requestId`의 재전송은 기존 작업을 반환하며 다시 생성하지 않습니다. 보존 시간은 준비 완료 시점부터 24시간이며 조회나 다운로드로 연장하지 않습니다. 복원 준비 데이터도 검증 완료 후 최대 24시간 보관합니다.

다운로드 도중 24시간이 지나면 해당 전송이 끝날 때까지 만료 정리를 유예합니다. 새 내보내기·로그아웃·초기화로 파일을 삭제하는 경우에는 진행 중 다운로드도 취소합니다. 작업 파일은 `DATA_DIR/.transfers/<작업 ID>/`에 저장합니다. 업로드한 원본 ZIP은 검증 완료 후 삭제하며 내보낸 ZIP은 교체·만료·로그아웃·초기화 시 삭제합니다. 서버에는 기존 데이터, 업로드 ZIP, 복원 준비용 암호화 파일과 인덱스를 함께 둘 공간이 필요합니다. 운영 데이터의 별도 암호화 백업에는 `.transfers`를 제외합니다.

대용량 업로드를 사용하는 배포에서는 리버스 프록시의 요청 본문 크기와 시간 제한도 조정해야 합니다. 앱의 업로드 전체 요청 제한은 2시간, 업로드 중 무응답 제한은 2분입니다.

## API와 구현

모든 API는 로그인 세션이 필요하며 쓰기 요청은 동일 출처를 검증합니다. 작업 상태와 다운로드는 생성한 세션에서만 접근할 수 있습니다. 새 작업 POST의 `requestId`로 중복 접수를 막습니다.

| API | 동작 |
| --- | --- |
| `GET /api/settings/transfers` | 현재 세션의 작업과 한도 |
| `POST /api/settings/transfers/export` | `{ requestId }`로 내보내기 접수, 202 반환 |
| `POST /api/settings/transfers/import` | `{ requestId, name, bytes }`로 업로드 준비, 202 반환 |
| `PUT /api/settings/transfers/:id/upload` | ZIP 본문을 파일로 스트리밍, 업로드 후 검증 시작 |
| `GET /api/settings/transfers/:id` | 작업 상태·진행량·검증 결과 |
| `GET /api/settings/transfers/:id/download` | 준비된 ZIP 스트리밍 다운로드 |
| `POST /api/settings/transfers/:id/restore` | `{ confirmed: true, password }`로 복원 접수, 202 반환 |
| `DELETE /api/settings/transfers/:id` | 적용 중 복원을 제외한 작업과 임시 파일 삭제 |

ZIP은 `settings.json`, `data/<종류>/<UTC 날짜>.json`, `manifest.json`으로 구성합니다. 설정과 날짜별 JSON은 평문이고 manifest는 형식 버전·내보낸 시각·파일별 해시·크기·건수를 담습니다. Deflate 및 ZIP64 처리는 [PKWARE ZIP 명세](https://pkware.cachefly.net/webdocs/casestudies/APPNOTE.TXT)를 기준으로 구현했으며 외부 압축 라이브러리와의 호환성도 테스트합니다.

`lib/data-transfers.mjs`는 작업 수명과 업로드·다운로드, `lib/archive-worker.mjs`는 압축·검증·암호화 준비, `lib/archive-data.mjs`는 데이터 형식, `lib/archive-zip.mjs`는 ZIP 입출력, `lib/restore-journal.mjs`는 적용과 재시작 복구를 담당합니다. 화면은 `public/data-transfer-ui.js`, 복원 확인은 기존 Danger Zone 팝업을 사용합니다.
