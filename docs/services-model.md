# 서비스와 감사 기록

이벤트는 제목·유형·서비스·일정·설명을 기록한다. 서비스 제안 목록은 이름·사용 여부·순서만 관리한다. 외부 호출과 결과 판정은 워크플로우에서 정의한다. 워크플로우는 별도의 정의·실행 기록을 저장하며 이벤트·서비스 검증에 실행 결과를 결합하지 않는다. 실행 기준은 [워크플로우 사용 안내](workflows.md)를 따른다.

## 서비스 선택

- 제안 목록 항목: `{ id, name, active, order }`. ID는 화면에서 자동 생성하며 저장한 ID는 유지한다. 사용하지 않는 서비스는 비활성화한다.
- 목록 선택: `{ kind: "catalog", id, label }`. 기존 이벤트의 선택 당시 표시명은 목록 이름을 바꾸어도 보존한다. 비활성 서비스를 새로 선택할 수 없지만 기존 선택은 편집 시 유지할 수 있다.
- 직접 입력: `{ kind: "custom", label }`. 표시명이 목록과 같아도 자동 연결하지 않는다. 빈 값은 제외하고 같은 직접 입력은 하나로 합친다.
- 이벤트의 `service` 문자열은 단일 서비스 입력과 표시용 호환 필드다. 다중 선택 요청에는 `services`를 사용한다.
- 서비스는 최대 200개, 한 이벤트의 선택은 최대 50개다. 목록·이벤트 변경은 버전 충돌을 검사하고 암호화된 변경 이력을 함께 저장한다.

## 내부 저장 구조

복호화된 내부 schema는 **5**다. `events`, `catalog: { version, services }`, `changes`, `workflows`, `workflowRuns`와 저장소 revision·생성·수정 시각으로 구성한다. 로그 관리 정책과 실행 결과는 `logPolicy`, `logMaintenance`, 서비스 상태·보류는 `serviceState`, 초기화 요청의 중복 방지 정보는 `resetRequests`에 둔다. Dry-Run 입력값은 각 워크플로우의 별도 설정으로 보관한다. AES-256-GCM 봉투 version 1을 사용한다.

- schema 5만 지원한다. 지원하지 않는 형식은 로그인 시 409로 알리며 자동 이관하거나 원본을 초기화·덮어쓰지 않는다.
- 저장소를 읽을 때 현재 모델의 필드만 메모리에 올린다. 사용하지 않는 최상위 필드는 다음 정상 저장부터 제외한다. 현재 이벤트·서비스·변경 기록·워크플로우·실행 이력은 유지한다.
- 로그인과 조회만으로 파일을 다시 쓰지 않는다. 저장 실패 시 현재 메모리·이력·원본을 유지한다. 데이터와 백업의 보관은 [데이터 보관 정책](specification.md#데이터-보관-정책)을 따른다.
- 손상 파일을 빈 저장소로 바꾸지 않는다. 새로 시작하려면 서버를 종료하고 기존 데이터 디렉터리를 보존한 뒤 비어 있는 `DATA_DIR`을 지정한다.

## 인증 API

모든 아래 API는 로그인 세션을 요구한다. 쓰기는 동일 출처와 JSON 요청을 검사한다.

| API | 역할 |
| --- | --- |
| `GET /api/services` | 서비스 목록과 버전 조회 |
| `PUT /api/services` | `{ version, services }` 저장 |
| `GET /api/events` | 기간과 페이지별 이벤트·저장소 revision 조회 |
| `GET /api/events/:id` | 이벤트 상세 조회 |
| `POST /api/events` | 이벤트 생성 |
| `PUT /api/events/:id` | 이벤트 버전을 확인해 수정 |
| `DELETE /api/events/:id` | 이벤트 버전을 확인해 삭제 |
| `GET /api/audit` | 변경 기록 조회, 기본 `kind=changes` |
| `GET /api/audit?kind=workflows` | 워크플로우 실행 기록 조회 |
| `GET /api/workflow-runs/:id` | 실행 당시 구성·입력·노드 결과 조회 |

감사 조회는 `from` 이상·`until` 미만 UTC 시각, 서비스 조건 `targetId`, `eventId`, `workflowId`, `search`, `page`, `limit`을 지원한다. `result`는 변경 종류 또는 실행 결과를, 워크플로우의 `mode`는 실행 계기(`manual`, `automatic`, `rerun`)를 검색한다. 페이지당 기본 25건, 최대 100건이다. 공유 비밀번호 인증으로 개인을 식별하지 않으며 사용자 변경은 공유 계정으로 표시한다.

감사 로그 종류는 `changes`, `workflows`만 지원한다. 지원하지 않는 종류를 요청하면 400, 존재하지 않는 상세 경로를 요청하면 404를 반환한다. 이벤트 기간·페이지 조회는 [기간별 로딩](specification.md#기간별-로딩), 워크플로우 저장·실행 API는 [사용 안내](workflows.md#인증-api)에 정의한다. 서버 재시작 후에는 웹 로그인으로 저장소 잠금을 해제한다.
