# 화면·동작 명세

## 공통

최상단 메뉴는 `캘린더 | 타임라인 | 워크플로우 | 감사 로그` 순서로 제공하며 스크롤해도 고정한다. 캘린더와 타임라인은 같은 날짜와 이벤트 데이터를 사용한다. 처음에는 오늘이 속한 월을 표시한다. 점검·불안정은 하나의 YELLOW 등급이며 선택 항목과 필터를 구분하지 않는다. 장애는 RED 등급이다. `instability` 입력은 `maintenance`로 정규화해 읽고 저장한다.

로그인 화면과 앱 최상단에서 다크 / 라이트 모드를 전환한다. 모든 화면과 팝업에 적용하며 날짜 선택, 스크롤 위치, 입력 중인 내용은 유지한다. 사용자의 선택은 브라우저 localStorage에만 저장하고 서버에 전송·저장하지 않는다. 저장된 선택이 없으면 브랜딩의 `defaultTheme`을 적용하며 필드를 생략하면 라이트 모드다. 브랜딩 파일 `branding.json`은 Git에서 제외하고, 파일 자체가 없어도 내장 기본 설정으로 실행한다. 배포 환경에서는 `BRANDING_FILE`로 외부 설정 파일을 지정할 수 있다.

로그인한 사용자는 상단 우측 사용자 메뉴의 시스템 설정에서 서비스 이름, 부제, 부제 표시 여부, 기본 테마, 표시 시간대, 비밀번호 안내문을 편집한다. 설정은 브랜딩 파일에 저장하며 현재 화면에 즉시 반영한다. 다른 열린 화면은 새로고침하면 적용한다. 저장은 인증·출처·입력값을 검증하고, 버전이 달라진 동시 편집은 덮어쓰지 않고 최신 설정 불러오기를 제공한다. 기본 테마 변경은 브라우저에 저장된 개인 테마 선택을 덮어쓰지 않는다. 비밀번호 안내문은 로그인 전에도 표시하며 최초 설정에서도 입력할 수 있다. 필드 제한과 기본값은 [브랜딩 설정](../README.md#브랜딩-설정)을 따른다.

시간대는 브랜딩의 `timezone`으로 설정하며 생략하면 `UTC`다. 설정 화면에서는 현재 값에 관계없이 기본 시간대 목록 전체를 드롭다운으로 제공하고, 목록에 없는 시간대는 `직접 입력…`으로 지정한다. 저장된 시간대가 목록에 없으면 직접 입력란에 원래 값을 표시한다. 브라우저의 OS 시간대 대신 이 값을 사용해 날짜·요일·오늘·월 집계·타임라인·입력·상세 시각을 계산한다. 이벤트 저장 시각은 항상 UTC이며 설정 변경으로 기존 데이터를 다시 저장하지 않는다. 서머타임 전환일도 실제 날짜 경계로 구분한다. 존재하지 않거나 중복되는 시각은 새 입력으로 거부하고, 기존 시각을 바꾸지 않은 편집에서는 원래 UTC 시각을 보존한다.

진행 상태의 강조는 브랜딩 시간대의 오늘에만 적용한다. `시작 ≤ 현재 < 종료`이거나 이미 시작한 종료 미정 이벤트는 배경을 조금 밝게 표시한다. 예정·종료 이벤트는 배경을 조금 어둡게 하고, 글자는 미세하게, 캘린더 배지와 타임라인 막대의 좌우 테두리는 그보다 더 약하게 표시한다. 테마와 유형별 가독성을 고려해 조정 폭을 달리한다. 여러 날 배지는 오늘 칸에 해당하는 배경·글자·가장자리만 조정하며 과거·미래 날짜의 표현과 선택 강조는 유지한다. 오늘의 목록 팝업에도 같은 진행 상태를 반영하고, 15초마다 또는 탭으로 돌아올 때 시작·종료·자정 경계를 다시 계산한다.

## 캘린더 뷰

- 년도: 좌우 이동, 직접 입력. 지원 범위는 1900~9998년.
- 월: 좌우 이동, 드롭다운. 오늘로 돌아가기 버튼 제공.
- 상단: 조회 중인 연월을 `2026.9`처럼 월의 자리 채움 없이 표시하고 이벤트 요약을 낮은 한 줄로 표시한다. 작은 화면에서는 요약을 두 열로 배치한다. 이벤트 추가 버튼은 날짜·필터 도구 모음에 배치한다.
- 표시 시간대와 동기화 상태는 최상단 사용자 메뉴에서 확인한다. 날짜 요약 옆에는 선택 날짜의 UTC 오프셋을 표시한다. 기록 조회에 실패하면 우측 하단에 연결 오류 안내와 **지금 다시 시도**를 제공한다. 활성 화면에서는 20초마다 자동 조회하고 조회 성공 시 오류 안내를 해제한다.
- 종료 시각 미정 요약에는 `∞` 아이콘을 사용한다. 중복되는 하단 범례, 소개 문구, 주말 색상 안내는 표시하지 않는다. 암호화 저장 방식은 README에서 설명한다.
- 날짜 grid: 일요일 시작 7열, 해당 월에 필요한 4~6주. 인접 월은 흐리게 표시하며 토·일요일의 날짜 숫자는 빨간색.
- 현재 시각: 오늘 날짜 칸의 가로 너비를 하루로 보고 날짜 제목 아래부터 하단까지 2px 적색 세로선과 상단 점을 표시한다. 날짜 오른쪽에는 `현재 HH:mm`을 표시한다. 이벤트 채움과 같은 브랜딩 시간대의 하루 경계로 위치를 계산하며 서머타임 전환일도 같은 비율을 사용한다. 15초마다, 탭으로 돌아올 때, 화면 크기를 바꿀 때 갱신하고 자정에는 오늘 강조와 선을 다음 날짜 칸으로 옮긴다. 오늘이 표시 범위 밖이면 숨긴다. 선은 이벤트 위에 표시하며 날짜·이벤트·더 보기 클릭을 가로막지 않는다.
- 조작 안내: 날짜 칸의 빈 영역에는 이벤트 추가, 날짜 숫자와 이벤트 배지에는 이벤트 목록 보기 툴팁을 표시한다. 배지 툴팁에는 기존 이벤트 정보도 함께 표시하고, 달력 하단에는 별도 안내 영역을 두지 않는다.
- 달력 높이: 상단과 하단 영역을 제외한 브라우저의 남은 높이를 주별로 나눈다. 날짜 칸은 최소 80px을 유지하며, 작은 화면에서는 페이지 스크롤을 허용한다.
- 당일 이벤트: 시작과 끝이 둥근 배지.
- 배지 경계: 배지의 좌우 가장자리에만 2px 선을 겹쳐 표시한다. 둥근 모서리와 주간 연결부 모양을 따르며, 유형별 색상을 라이트 모드에서는 짙게, 다크 모드에서는 밝게 표시한다. 제목 공간과 날짜별 시간 비율을 유지하고, 여러 날 이벤트의 연결 표시와 `∞`도 함께 표시한다.
- 배지 채움: 날짜마다 하루 중 이벤트가 진행된 위치와 길이를 원래 채움 색으로 표시하고, 시작 전·종료 후는 같은 계열의 더 어두운 색으로 표시한다. 예를 들어 09:00~18:00 이벤트는 앞 37.5%, 가운데 37.5%, 뒤 25%로 나뉜다. 여러 날 이벤트는 시작일·중간일·종료일을 각각 계산하며, 각 구간은 날짜 칸 경계에 맞춘다. 브랜딩 시간대의 실제 하루 길이를 기준으로 하므로 서머타임 전환일도 타임라인과 같은 비율을 사용한다. 다크·라이트 모드 모두 제목과 아이콘은 채움 위에 표시한다.
- 여러 날 이벤트: 같은 주에서는 하나의 막대로 연결한다. 주를 넘기는 부분은 잘린 모서리와 연결 표시를 사용한다.
- 종료 시각 미정: 종료가 정해지기 전까지 날짜마다 포함되며 각 주의 연속 막대 끝에 `∞`를 표시한다. 시작일은 시작 시각부터, 이후 날짜는 하루 전체를 원래 색으로 채운다. 이는 종료 시각 미정을 나타내며 현재까지의 경과 시간 표시는 아니다.
- 배지 클릭: 마우스로 클릭한 날짜의 이벤트 목록 팝업을 열고 선택한 이벤트에 테두리와 `선택한 이벤트` 표시를 붙인다. 해당 항목으로 키보드 초점을 옮기고 목록 안에서 스크롤하여 보이게 한다. 키보드로 배지를 활성화하면 해당 배지 구간의 첫날 목록을 연다.
- 날짜 숫자 클릭: 이벤트 개수와 관계없이 해당 날짜의 목록 팝업을 연다. 날짜 숫자나 더 보기로 열면 특정 이벤트를 강조하지 않는다. 표시할 이벤트가 없으면 빈 상태 안내와 해당 날짜의 이벤트 추가 버튼을 제공한다. 날짜 칸의 빈 영역 클릭은 새 이벤트 추가로 유지한다.
- 과밀 날짜: 날짜 칸 높이에 따라 주간 이벤트 레인 1~3개를 표시한다. 날짜 숫자와 더 보기 버튼의 공간을 확보하고, 숨겨진 이벤트 수를 `+N 더 보기`로 표시하며 해당 날짜의 전체 이벤트 목록을 팝업으로 연다. 화면 크기를 바꾸면 표시 개수와 숨겨진 수를 함께 갱신한다.
- 목록 팝업: 조회 날짜의 연도와 시간대를 표시하고 이벤트마다 시작·종료를 각각 보여준다. 조회 날짜와 같은 시각은 `당일 HH:mm`, 다른 날짜의 시각은 `YYYY.MM.DD HH:mm`으로 표시한다. 종료 시각 미정은 시작 시각과 함께 `종료 미정 ∞`로 표시하며, 목록 항목 클릭 시 이벤트 정보 팝업을 연다. 정보 팝업의 `캘린더에서 보기 / 타임라인에서 보기`는 조회 날짜를 유지해 해당 이벤트를 강조한다. 날짜가 이벤트 기간 밖이면 시작 날짜로 이동하고, 이벤트를 가리는 유형 필터는 해제한다. 캘린더의 표시 행 수를 넘는 이벤트도 선택 시 보이는 행에 배치한다.
- 목록 팝업 배경: 각 이벤트 항목의 전체 가로 너비를 조회 날짜의 하루로 보고, 캘린더 배지와 같은 계산·유형별 색상으로 진행 시간의 위치와 길이를 채운다. 이벤트 외 시간에는 어두운 색과 옅은 빗금을 표시한다. 이전 날부터 이어지거나 다음 날까지 진행하는 이벤트는 조회 날짜 범위로 잘라 표시하고, 종료 미정은 시작 이후부터 하루 끝까지 채운다. 제목·서비스·시작·종료 시각은 배경 위에 표시하며 다크·라이트 모드에서도 읽을 수 있어야 한다.
- 목록 팝업 현재 시각: 조회 날짜가 오늘이면 각 이벤트 항목에 캘린더와 같은 비율의 적색 세로선과 상단 점을 표시하고, 팝업 상단 시간대 옆에 `현재 HH:mm`을 한 번 표시한다. 15초마다 갱신하며 자정이 지나 조회 날짜가 오늘이 아니게 되면 선과 시간 문구를 숨긴다. 과거·미래 날짜에는 표시하지 않으며 항목 클릭을 방해하지 않는다.
- 날짜 배경: 선택한 유형 필터에 해당하면서 그날과 겹치는 이벤트 중 가장 중대한 색을 옅게 표시한다. 장애 > 점검/불안정 > 없음.

## 타임라인 뷰

- 상단 요약과 시간축 헤더에 현재 조회 날짜를 `2026.9.9`처럼 월·일의 자리 채움 없이 `YYYY.M.D` 형식으로 표시한다. 날짜 이동과 좌우 스크롤에 맞춰 함께 갱신한다.

- 날짜 좌우 이동, 직접 선택, 오늘로 이동.
- 가로축은 날짜별 00:00~23:59, 세로축은 해당 날짜와 겹치는 이벤트 목록.
- 이벤트가 없거나 필터 결과가 비어 있어도 왼쪽 이벤트 열과 구분선을 타임라인 본문 하단까지 유지한다. 빈 상태 안내는 오른쪽 시간 영역에 표시한다.
- 실제 오늘에 현재 시각 세로줄을 표시하고 15초마다 갱신한다.
- 당일 완결: 시작·종료 시각 사이에 막대를 표시한다.
- 이전 날짜에 시작해 당일 종료: 왼쪽을 자정에 맞춰 자르고 실제 종료 시각에 막대를 닫는다.
- 당일 시작해 이후 날짜에 종료: 실제 시작 시각에서 오른쪽 자정까지 이어지는 막대를 표시한다.
- 종료 시각 미정: 시작 시각 또는 자정부터 오른쪽 끝까지 표시하고 `∞`를 붙인다.
- 좌우 스크롤: 브라우저에 가까운 7일을 유지하고 양 끝 근처에서 날짜 범위를 이동시킨다. 현재 화면 중심의 날짜에 맞춰 이벤트 행을 갱신한다.
- 시간 눈금을 좌우로 드래그해 스크롤할 수 있다. 날짜 범위가 바뀌어도 드래그가 이어지고, 눈금 밖에서 손을 떼거나 조작이 취소되면 종료한다.
- 하단 안내 영역 없이 시간 눈금의 날짜 이동 툴팁과 이벤트 제목·막대의 상세 보기 툴팁으로 조작 방법을 안내한다.
- 이벤트 제목과 막대 클릭 시 상세 조회·편집·삭제 가능.

## 감사 로그

- 캘린더·타임라인·워크플로우와 같은 요약 헤더, 여백, 도구 모음과 목록 컨테이너를 사용한다. 왼쪽에는 앱 시간대 기준의 오늘 날짜와 UTC 시차를 표시한다.
- 상단은 전체 기록·변경 기록·워크플로우 실행·조회 결과의 네 항목으로 구성한다. 전체 기록은 변경 기록과 워크플로우 실행 수의 합이다. 조회 결과는 선택한 종류와 검색 조건에 맞는 전체 개수이며, 페이지를 이동해도 바뀌지 않는다.
- 도구 모음의 버튼은 워크플로우 실행·변경 기록 순서로 배치하며, 최초 진입과 다시 로그인한 뒤에는 워크플로우 실행을 기본 선택한다. 이름·식별자 검색과 새로고침을 제공한다. 서비스·이벤트 ID·워크플로우 ID 조건은 접을 수 있는 필터 영역에 모은다. 관련 이벤트에서 감사 기록을 열면 변경 기록을 선택하고 해당 필터를 펼친다.
- 조회 기간은 앱 시간대의 오늘 기준 최근 1개월이 기본이다. 시작일·종료일과 1일·1주·2주·1개월·3개월·6개월·1년 간편 버튼은 항상 표시한다. 시작일과 종료일의 기록을 모두 포함하고, 간편 버튼은 입력 중인 다른 조건을 함께 적용해 첫 페이지부터 즉시 조회한다.
- 1일은 오늘, 1주·2주는 오늘을 포함한 7일·14일이다. 월·년은 오늘에서 달력 단위로 거슬러 계산하고 해당 날짜가 없으면 말일로 보정한다. 간편 기간은 새로고침할 때도 오늘을 기준으로 갱신한다. 날짜를 직접 바꾸면 간편 선택을 해제하고 조회 버튼으로 적용한다. 검색 조건 초기화는 최근 1개월로 복원하며, 날짜를 모두 비우면 기간 제한 없이 조회할 수 있다.
- 새로고침 버튼을 누르면 내부 아이콘이 0.6초 동안 한 바퀴 회전한다. 애니메이션과 조회가 모두 끝날 때까지 버튼을 비활성화하고 연속 클릭으로 추가 요청을 보내지 않는다. 조회 실패 후에도 다시 사용할 수 있으며, 동작 줄이기 설정에서는 회전을 생략하고 동일한 클릭 제한을 적용한다.
- 변경 기록은 기록 시각·변경 내용·대상·작업자 순서의 표로 표시하며, 변경 전후 값은 상세 팝업에서 확인한다. 워크플로우 실행 상세는 당시 구성·입력·노드별 결과를 표시한다.
- 다크·라이트 모드와 모바일 배치를 제공한다. 좁은 화면에서는 표 안에서 좌우로 스크롤하고, 상세 팝업의 변경 전후 값은 세로로 배치한다.

실행 상세는 당시 구성, 입력, 진행 경로, 노드별 출력·오류·HTTP 시도를 표시한다. 종료된 일반 실행은 당시 버전·입력과 현재 비밀 변수로 처음부터 다시 실행한다. 서비스 실행은 최신 정의·현재 상태로 재평가한다. 두 동작 모두 원래 실행과 연결된 새 기록을 만든다. 서버 중단으로 끝나지 않은 실행은 중단 처리하고 자동 재개하지 않는다.

설정·API·변수·제한의 상세 기준은 [워크플로우 사용 안내](workflows.md)에 정의한다.

## 데이터 보관 정책

### 기간별 로딩

- 암호화 관리 파일(`dailyStorageVersion: 2`)에는 설정과 날짜 파일별 조회 요약을 저장한다. 이벤트·감사 로그·실행 본문은 요청한 기간에 해당하는 파일만 읽는다. 종료 미정·여러 해에 걸친 이벤트는 시작·종료 범위 요약으로 포함 여부를 판단한다.
- `GET /api/events?from=<UTC ISO>&until=<UTC ISO>&page=1&limit=1000`: 시작 이상·종료 미만 구간과 겹치는 이벤트를 반환한다. 두 시각은 함께 지정하며 최대 366일이다. 기본 페이지 크기는 100, 최대 1,000이며 `events`, `revision`, `total`, `page`, `limit`, `pages`를 반환한다. 정렬은 파일 날짜 내림차순, 같은 날짜의 파일 종류순, 파일 안의 시작 시각 내림차순·ID 오름차순이다. 기간 생략 시에도 페이지 단위로 반환한다.
- 다음 페이지에 첫 응답의 `revision`을 보내면 조회 중 변경을 409로 감지한다. 화면은 첫 페이지부터 한 번 재조회하며, 이전 날짜 요청을 취소하고 늦은 응답을 무시한다. 캘린더는 표시 월의 앞뒤 7일, 타임라인은 선택일 전 14일·후 14일을 미리 읽고 범위를 벗어나면 교체한다.
- `GET /api/events/:id`는 현재 표시 기간 밖의 이벤트 상세도 조회한다. 감사 로그에서 관련 이벤트를 열거나 워크플로우 입력을 지정할 때 전체 이벤트를 읽지 않는다. 수동 실행의 이벤트 선택은 100건씩 페이지를 이동한다.
- 감사 API의 `counts`는 전체 변경·실행 건수를 제공한다. 목록은 기간별 파일을 순회하며 요청한 페이지에 필요한 참조만 정렬한다. 워크플로우는 저장된 종료일과 별개로 **접수 시각**을 조회 기준으로 사용한다. 워크플로우 목록 통계는 파일 요약을, 예약 실행은 현재 점검 구간의 이벤트와 진행 중 실행을 사용한다.
- 기록 ID·중복 요청 키의 위치는 암호화된 `lookup` 파일에 분할한다. 수정·삭제는 해당 날짜와 이동 목적지만 읽으며 만료 작업은 오래된 본문을 읽지 않고 파일·색인을 정리한다. 백업·복원에는 `lookup` 디렉터리도 포함한다.
- 복호화 파일 캐시는 파일 크기 합계 16MiB까지 유지한다. 요청 처리 중인 파일·결과와 JavaScript 객체의 실제 메모리는 별도다. `dailyStorageVersion: 1`은 잠금 해제 시 날짜 파일을 순회해 색인을 만들고 다음 정상 저장에서 버전 2로 기록한다. 지원하지 않는 저장소 schema는 이관하지 않는다.

### 보관 설정

시스템 설정에 **로그 관리 정책** 그룹을 제공한다. 설정은 암호화 저장소에 저장하고, 서버에서 범위·cron 문법·버전 충돌을 검증한다. 정책 변경 전후도 감사 로그에 남긴다.

| 하위 옵션 | 기본값 | 허용 범위·기준 |
| --- | --- | --- |
| 실행 일정 (cron) | `0 3 * * *` | 분·시·일·월·요일의 5개 필드. 서비스 시간대 기준 매일 03:00. 숫자·와일드카드·범위·목록·간격 지원 |
| 이벤트 데이터 보관 | 1,825일 | 최소 30일, 최대 3,650일의 정수 |
| 감사 로그 로테이션 | 90일 | 최소 7일, 최대 180일의 정수 |

- 이벤트는 UTC 종료일별, 감사 변경 기록은 UTC 기록일별, 종료된 워크플로우 실행은 UTC 종료일별 암호화 JSON에 저장한다. 종료 미정 이벤트는 시작일별 별도 디렉터리, 진행 중인 실행도 별도 디렉터리에 저장해 만료 대상에서 제외한다. 종료일을 수정하면 해당 날짜 파일로 이동한다.
- cron은 **UTC 오늘 − 보관 일수**보다 이전인 날짜 파일을 삭제한다. 기준일 당일 파일은 유지한다. 예를 들어 UTC 2026-09-10에 30일 보관이면 2026-08-11 이전 파일을 삭제한다. 날짜 전체가 만료된 뒤 삭제하므로 개별 기록은 설정 일수보다 최대 하루 더 보관될 수 있다.
- 이벤트 원본은 이벤트 보관 기간을, 변경 전후 스냅샷과 실행 입력은 감사 로그 기간을 따른다. 만료 정리 시 `.bak`의 참조도 갱신해 삭제한 파일에 의존하지 않게 한다. 별도 외부 백업은 운영 절차로 보관·삭제한다.
- 예약 실행마다 `감사 로그 로테이션`과 `이벤트 만료 처리`를 시스템 작업자로 기록한다. 처리 건수(0건 포함), 실행 ID, 적용 기간, 삭제 기준 시각, cron·시간대, 만료 이벤트 ID·대상 파일·결과를 남긴다. 처리 기록 자체도 감사 로그 보관 기간을 따른다.
- 날짜 파일은 변경된 날만 새 세대로 저장한다. 작은 암호화 관리 파일에 설정·파일 목록을 두며 파일 기록·동기화가 끝난 뒤 목록을 교체한다. 관리 파일 저장 전 실패하면 기존 데이터와 파일 참조를 유지한다.
- 정리 대상·미완료 감사 기록·예약 실행 표시는 함께 저장한다. 이후 실제 파일을 삭제하고 감사 기록을 완료로 갱신한다. 삭제 목록이 저장되어 있어 중단·삭제 실패·완료 기록 저장 실패 후에도 다음 점검에서 재개할 수 있다. 삭제 실패는 감사 로그에 남기며 실패 기록도 저장할 수 없으면 설정 화면에 알린다.
- 잠금이 해제된 서버가 15초마다 예약 시각을 점검한다. 완료한 일정은 저장소에 남겨 같은 분의 중복 점검·재시작에서 다시 실행하지 않는다. 서버 중단·잠금 중 놓친 일정은 다음 예약 시각에 처리한다.
- `GET /api/settings/log-policy`로 정책·시간대·최근 결과·오류를 조회하고, `PUT /api/settings/log-policy`에 `{ policy: { version, cron, eventRetentionDays, auditRetentionDays } }`를 보내 저장한다. 인증과 쓰기 출처 검증은 다른 설정 API와 동일하다. 기존 저장소에 정책이 없으면 기본값을 사용하며 조회만으로 파일을 다시 쓰지 않는다.

## 인증과 이벤트 편집

- 암호화 비밀번호 최초 설정, 로그인, 로그아웃.
- 암호화 키는 서버 메모리에만 유지. 파일에는 암호화된 JSON 상태 저장.
- 공유 비밀번호를 아는 사람은 같은 읽기·쓰기 권한을 가진다.
- 수기 이벤트 추가·제거·편집.
- 시작·종료 입력: 날짜 달력과 시(`00`~`23`)·분(`00`~`59`) 선택기를 사용해 24시간제로 고정한다. 오전/오후 선택은 표시하지 않는다. 종료 미정이면 종료 날짜·시·분을 함께 비활성화한다.
- 이벤트 필드: 제목, 유형, 서비스(선택), 시작, 종료 또는 종료 미정, 상세 내용(선택).
- 잘못된 키·손상된 파일은 초기화하지 않는다. 로그인 가능한 사용자는 Danger Zone에서 비밀번호를 재확인해 초기화한다. 비밀번호를 분실한 경우 서버 운영자가 `DATA_DIR/SETUP_COMPLETE.txt`를 삭제하여 전체 초기화한다.

## 워크플로우

- 목록에서 이름 검색·생성·삭제 확인과 ON/OFF를 제공하고 실제 마지막 실행 상태·실행일·성공일·소요 시간을 표시한다. 새 워크플로우는 OFF다.
- 이름을 누르면 노드 편집 화면으로 이동한다. 그래프 헤더에 이름·연필·저장 상태를 한 번 표시한다. 저장 버튼으로 정의·컨텍스트 주입 값·기존 비밀 변수 삭제·위치를 반영하고 되돌리기는 마지막 저장 상태를 복원한다. 컨텍스트 값 주입 노드는 더블 클릭 팝업에서 키·값 목록을 편집하고 실행 시 `context.키`를 추가·갱신한다. 비밀 변수 UI는 기존 값이 있을 때만 표시하며 UI·API 모두 삭제만 지원한다. 동시 수정은 버전 충돌로 알린다.
- 다이어그램은 본문 전체를 사용하며 작업 도구·노드 목록·노드 설정·확대 도구를 캔버스 위 패널로 표시한다. 패널을 접고 펼칠 수 있고 화면 맞춤은 열린 패널을 피한다. 좁은 화면에서는 패널 하나씩 열고 노드 설정을 하단에 표시한다. 상세 조작은 [편집 화면](workflows.md#편집-화면)을 따른다.
- 노드 이동·추가·복제·자동 정렬은 18px dot grid와 (0, 0)~(5004, 5004) 배치 영역에 맞춘다. 5004는 5000에 가장 가까운 도트 좌표다. 굵은 경계선을 표시하고 노드·연결점·출력 라벨이 안쪽에 머물도록 제한한다. 긴 흐름은 자동 정렬 시 여러 열로 나누며, 영역 밖에 배치된 기존 정의는 편집기에서 영역 안으로 정렬한다. 배경 드래그로 패닝하고 마우스 휠로 확대·축소한다. 조작 안내는 툴팁으로 제공한다.
- 카메라가 바라보는 화면 중앙의 다이어그램 좌표도 `(0, 0)`~`(5004, 5004)`로 제한한다. 배경 드래그·방향키 이동·줌·화면 맞춤·노드 표시·화면 크기 변경에 같은 제한을 적용한다. 경계에 닿은 뒤 반대로 드래그하면 즉시 안쪽으로 이동한다.
- 이벤트 시작·종료는 입력한 시각에 실행한다. 지난 시각의 등록·수정, OFF 구간, 서버 중단 기간은 소급 실행하지 않는다. cron은 다섯 필드와 시간대를 사용한다.
- 서비스 상태 변경은 현재 활성 이벤트를 서비스 문자열별로 집계하고 심각도가 달라지면 실행한다. 최초 평가는 기준점만 저장한다. 서비스별 직렬화와 불명 결과 보류를 적용하며 [서비스 상태 규칙](workflow-authoring.md#서비스-상태-변경-트리거)을 따른다.
- 실행 가능한 구성은 트리거 하나와 연결된 비순환 그래프다. 컨텍스트 주입·조건·switch 분기·목록 검색·날짜 시각·HTTP·종료 노드를 지원한다. HTTP 상태·응답 본문 등을 비교해 작성자가 성공·실패·확인 필요·생략을 정의한다. 노드별 설정은 [JSON 작성 안내](workflow-authoring.md)를 따른다.
- HTTP 조회 요청의 통신 오류는 실패 종료·계속 진행·오류 분기 중 선택한다. 변경 요청의 불명 결과는 확인 필요로 처리한다. 자동 재시도는 기본 0회다. HTTP 4xx·5xx 자체는 통신 오류로 취급하지 않는다.
- OFF에서도 저장된 구성으로 수동 실행할 수 있다. 이벤트 트리거는 입력 이벤트를 선택한다. 삭제하면 대기·실행 중 작업을 중지하고 이력은 보관 정책까지 남긴다.
- 편집 화면 상단의 Dry-Run 테스트는 저장 전 구성을 대상으로 이벤트·트리거 초기값과 노드별 HTTP 응답·통신 오류를 입력받아 모의 실행한다. 기준 시각·컨텍스트 주입·검색·조건·종료를 계산하고 팝업에 경로·출력·오류를 표시한다. 입력값은 워크플로우별 별도 버전으로 암호화 저장하여 다음 팝업·새로고침·재시작 후 복원한다. 테스트와 입력값 저장은 감사 로그·실행 이력을 만들지 않고 외부 API·자동 실행·서비스 보류에 영향을 주지 않는다.
- 서비스 상태 변경 Dry-Run은 등록 일정의 시작·종료와 대상 서비스를 선택해, 같은 시각의 중첩 일정 전체를 반영한 이전/이후 상태·관련 이벤트를 채울 수 있다. 노드의 대상 서비스 설정을 따르며, 상태 변화가 없으면 일정 재현 테스트의 후속 실행을 생략한다. 계산된 값과 출처는 보존하고 직접 수정도 지원한다. 현재 등록된 일정 기준으로 계산하며 실행 세대는 현재 저장된 세대를 기준으로 모사한다. 조회·계산은 실제 서비스 상태와 감사 로그를 변경하지 않는다.

## Danger Zone

로그인 후 사용자 메뉴 → 시스템 설정 → **Danger Zone**에서 초기화할 대상을 선택합니다. 초기화 동작은 **대상 확인 팝업 → 확인 → 별도의 현재 비밀번호 입력 팝업 → 초기화** 순서입니다. 취소하거나 비밀번호가 틀리면 데이터를 삭제하지 않습니다.

같은 그룹에 **데이터 내보내기 / 데이터 복원하기**를 제공합니다. 내보내기는 별도 스레드에서 복호화 ZIP을 만들고 완료 후 날짜 이름의 다운로드 버튼을 표시합니다. 복원은 파일 업로드·검증을 먼저 진행하고 검증한 건수와 복원 버튼을 표시합니다. 복원 버튼에서 확인과 비밀번호 재입력을 거친 후 이벤트·서비스·워크플로우·감사 로그·설정을 전체 교체하며 현재 비밀번호를 유지합니다. 상세 흐름, 한도, 임시 파일 정리와 중단 복구는 [데이터 내보내기와 복원](data-transfer.md)에 정의합니다.

| 동작 | 삭제하는 항목 | 유지하는 항목 |
| --- | --- | --- |
| 감사 로그 초기화 | 변경 기록, 워크플로우 실행 이력. 대기·진행 중 실행을 먼저 중지 | 이벤트, 서비스, 워크플로우 구성, 설정 |
| 이벤트 초기화 | 모든 이벤트 | 서비스, 워크플로우, 기존 감사 기록. 이미 접수한 실행은 당시 입력으로 계속 진행 |
| 워크플로우 초기화 | 모든 워크플로우 구성·비밀 변수. 대기·진행 중 실행을 중지 | 이벤트, 서비스, 기존 실행 이력, 설정 |
| 시스템 초기화 | 위 항목 전체, 서비스 목록, 시스템 설정·비밀번호, 앱의 관리·날짜·백업 파일 | 운영자가 별도로 보관한 외부 백업과 앱이 관리하지 않는 파일 |

시스템 초기화는 모든 세션을 종료하고 **처음 시작하기** 화면에서 새 비밀번호를 받습니다. 앱이 관리하는 브랜딩 파일도 제거하여 기본 설정으로 되돌립니다. 서버 재시작은 필요하지 않습니다. 이미 외부 API에 적용된 호출은 초기화로 되돌리지 않습니다.

서버는 로그인 세션·동일 출처·현재 비밀번호를 검증합니다. 최근 5분 동안 비밀번호 확인을 5번 실패하면 재시도를 제한합니다. 처리 중 중복 제출을 막고, 같은 요청 식별자를 재전송해도 이후 데이터를 다시 지우지 않습니다. 초기화가 진행되는 동안 새 API 작업을 받지 않고 먼저 접수한 쓰기를 마친 뒤 적용합니다.

부분 초기화는 변경 상태를 원자적으로 저장하고 앱의 직전 백업도 초기화 후 상태로 교체합니다. 선택하지 않은 데이터의 기존 감사 스냅샷은 표의 범위대로 보존합니다. 이전 날짜 파일 삭제에 실패하면 화면에 미완료 정리를 알리며 다음 저장에서 재시도합니다. 시스템 초기화는 정리 시작을 기록하고 파일 삭제 도중 중단되면 같은 요청 또는 서버 재시작에서 이어서 처리합니다. 완료 전에는 일반 데이터 API를 차단합니다.

인증 API: POST /api/settings/reset. 본문은 target(audit/events/workflows/system), confirmed: true, requestId(8~100자의 영문·숫자·하이픈·밑줄), password입니다. 비밀번호는 저장하거나 로그에 남기지 않습니다. 로그인할 수 없는 비밀번호 분실 상황은 서버 운영자의 별도 초기화 절차를 사용합니다.

## 서버 파일을 통한 전체 초기화

최초 설정 성공 시 `DATA_DIR/SETUP_COMPLETE.txt`에 `true`를 기록합니다. 운영자가 이 파일을 삭제하면 기존 비밀번호 없이 Danger Zone의 시스템 초기화와 같은 범위로 데이터를 삭제하고 모든 세션을 종료합니다. 완료 후 웹의 **처음 시작하기**에서 새 비밀번호를 설정하며 완료 파일을 재생성합니다. 로그인 화면을 열어 둔 경우에도 상태를 갱신해 최초 설정으로 전환합니다.

서버 시작·웹 접속 및 약 1초 간격으로 삭제를 감지합니다. 실행 중 워크플로우와 정리 작업을 중지하고 먼저 접수한 API 요청을 마친 뒤 초기화합니다. 파일 내용 변경(`false`, 빈 내용 등), 잘못된 파일 형식, 읽기 실패는 삭제로 취급하지 않습니다. 정리 실패 시 일반 API와 최초 설정을 차단하며 `.system-reset-pending`을 유지합니다. 원인을 해결하고 서버를 재시작하면 삭제를 재개합니다.

서버 시작 시 내부 파일 `.setup-marker-enabled`가 없는 초기 설정된 저장소에는 데이터를 보존하며 완료 파일과 내부 파일을 생성합니다. 내부 파일이 있으면 완료 파일 삭제를 초기화 요청으로 처리합니다. 내부 파일은 직접 삭제하지 않습니다. 백업·복원 시 두 파일을 데이터 파일과 함께 취급합니다. 외부에 별도로 보관한 백업과 이미 적용된 외부 API 동작은 초기화 범위에 포함되지 않습니다.
