# 이벤트 메모와 본문

이벤트는 운영자가 작성하는 **메모**와 Text 또는 HTML 형식의 **본문**을 별도로 저장한다. 기존 설명은 메모로 표시하며 본문으로 이동하거나 복사하지 않는다.

## 입력과 조회

작성·편집 창에서 메모, 본문 형식, 본문을 입력한다. **본문 미리보기**는 저장 전 내용을 표시한다. HTML 모드에서는 HTML 소스를 입력하며, Text/HTML 전환은 원문을 변환하지 않고 해석 방식만 바꾼다. 메모만 수정할 때는 본문의 원래 줄바꿈과 앞뒤 공백도 유지한다.

정보 팝업은 메모와 본문을 구분해서 표시한다. Text는 태그를 실행하지 않고 줄바꿈을 유지한다. HTML은 밝은 배경의 독립된 영역에 표시하여 앱의 다크·라이트 테마가 이메일의 글자색·배경색에 간섭하지 않게 한다. 긴 본문과 넓은 표는 표시 영역 안에서 스크롤한다. 이벤트 복제는 메모·본문 원문·본문 형식을 모두 복사한다.

## API와 기존 데이터 호환

| 필드 | 형식과 제한 | 누락된 기존 데이터의 기본값 |
| --- | --- | --- |
| `description` | 메모 문자열, 최대 4,000자. 기존 저장 키 유지 | 기존 처리 유지 |
| `body` | 본문 문자열, UTF-8 기준 최대 128KiB. 앞뒤 공백·줄바꿈·HTML 원문 보존 | `""` |
| `bodyFormat` | `"text"` 또는 `"html"` | `"text"` |

본문 형식을 태그 유무로 추측하지 않는다. `null`, 문자열이 아닌 본문, 지원하지 않는 형식은 거부한다. 빈 HTML 본문도 허용하며 지정한 `html` 형식은 유지한다.

```json
{
  "title": "협력사 점검 안내",
  "category": "maintenance",
  "services": [],
  "start": "2026-09-09T00:00:00.000Z",
  "end": "2026-09-09T01:00:00.000Z",
  "description": "안내 수신 후 영향 범위 확인",
  "body": "<table><tr><th>대상</th><td>서비스 A</td></tr></table>",
  "bodyFormat": "html"
}
```

생성은 `POST /api/events`, 수정은 `PUT /api/events/:id`에 `version`을 포함한다. 생성·수정 JSON 요청의 전체 한도는 1MiB이며, JSON 이스케이프 후에도 본문 자체의 128KiB 한도를 사용할 수 있다.

- 내부 schema 5와 ZIP 형식 version 1을 유지한다. 새 필드가 없는 기존 저장소와 백업도 읽을 수 있다.
- 이벤트 목록·상세 조회와 워크플로우 실행·재실행·Dry-Run에서는 누락 필드에 기본값을 적용한다. 조회·평가를 위한 기본값 적용만으로 이벤트 파일을 다시 쓰거나 이벤트 버전을 올리지 않는다.
- 기존 이벤트를 수정하면 해당 이벤트에 기본값을 기록한다. 같은 날짜의 다른 기존 이벤트까지 일괄 변환하지 않는다.
- 구버전 API 이용자가 본문 필드를 보내지 않고 수정하면 저장된 본문과 형식을 유지한다. 본문을 지우려면 `body: ""`를 명시한다. `bodyFormat`만 생략한 수정도 기존 형식을 유지한다.
- 생성·수정 감사 기록에는 메모와 본문 원문·형식을 포함한다. 감사 화면은 본문 원문을 텍스트로 표시한다. 기존 감사 기록 자체를 재작성하지 않는다.
- ZIP 내보내기·복원은 원문을 보존한다. 본문이 없는 기존 ZIP은 복원 후 조회할 때 기본값을 적용한다.

워크플로우의 `event.description`은 메모, `event.body`는 본문 원문, `event.bodyFormat`은 형식이다. HTML은 워크플로우에서도 문자열이며 실행하지 않는다. 기존 Dry-Run의 필드·총 입력 크기 제한은 유지하므로, 큰 본문을 포함한 일정 전체가 초기값 제한을 넘으면 필요한 값을 직접 입력한다.

## HTML 표시 범위

표와 셀 병합, 문단, 제목, 목록, 인용문, 강조, 링크를 지원한다. 인라인 스타일과 스타일시트의 기본 규칙·미디어 조건에서 글자·배경색, 글꼴·크기, 정렬, 줄 간격, 테두리, 여백, 표 배치와 너비·높이를 유지한다. 모든 이메일 프로그램의 전용 서식이나 동일한 픽셀 배치를 보장하지 않는다.

스크립트, 이벤트 핸들러, 폼, 중첩 프레임, 객체, SVG/MathML, 문서 리다이렉트, 외부 스타일·폰트, URL을 사용하는 배경 등은 표시 대상에서 제외한다. 이미지·첨부파일·`cid:` 이미지는 불러오지 않으며 이미지의 대체 텍스트가 있으면 표시한다. 현재 본문 필드만으로 이미지나 메일 파일을 보관하지 않는다.

링크는 절대 `http`·`https` 주소만 제공한다. 외부 주소는 앱의 이동 확인 팝업을 거쳐 새 탭으로 열고 referrer와 원래 창 참조를 전달하지 않는다. 같은 origin 주소는 확인 없이 새 탭으로 연다. 브라우저 컨텍스트 메뉴에 대한 제한은 [공통 링크 동작](specification.md#공통)과 같다.

수집·저장 원문에 HTML 정제를 적용하지 않는다. 표시용 사본에 DOMPurify와 CSS 허용 목록을 적용하고, 스크립트·폼·팝업·상위 이동이 금지된 iframe에서 표시한다. iframe의 `allow-same-origin`은 부모 화면의 링크 확인 처리에 사용하며 `allow-scripts`는 허용하지 않는다. 별도 CSP는 외부 리소스·폼·기준 주소 변경을 차단한다. HTML 정제와 격리는 원문의 발신자나 진위를 검증하는 기능이 아니다.
